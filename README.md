## 1. Калибровка камеры

Калибровка необходима для определения оптических параметров вашей камеры (матрицы камеры и коэффициентов дисторсии), чтобы точно определять 3D-положение ArUco-маркеров.

Калибровка выполняется из веб-пульта: откройте **Настройки → Камера**. Там можно скачать готовую шахматную доску A4. Стандартный шаблон содержит 9×7 чёрно-белых клеток, то есть 8×6 внутренних пересечений, с размером клетки 25 мм. Его нужно печатать в альбомной ориентации, в масштабе 100%, без автоматического вписывания в страницу.

После нажатия «Начать» мастер автоматически собирает 25 разных резких кадров. Держите доску целиком в кадре, перемещайте её к четырём углам, меняйте расстояние и наклон. Мастер сообщает, видит ли он доску, почему отклонил кадр и какое положение нужно показать следующим. После сбора нажмите «Рассчитать», проверьте RMS-ошибку и новый оптический центр, затем нажмите «Применить».

Новая матрица записывается атомарно в `shared_config/camera_info.yaml` и сразу передаётся детектору. Предыдущий файл сохраняется рядом как `camera_info.yaml.previous`.

## 2. Управление ArUco метками

База данных меток находится в файле конфигурации [tags_config.yaml](file:///home/panik_bel/ros2_ws/src/fake_tag_publisher/config/tags_config.yaml).

### Какое семейство меток использовать?
По умолчанию в проекте настроено семейство **DICT_4X4_100** (или **DICT_4X4_50**). 
* Маркеры этого семейства имеют размерность $4 \times 4$ точки, что делает их простыми для распознавания на расстоянии и при слабом освещении.
* Вы можете генерировать и скачивать маркеры этого семейства с помощью бесплатных онлайн-генераторов ArUco (например, [Aruco Generator](https://chev.me/arucogen/)). Укажите словарь `Original ArUco` или `4x4`, введите нужный ID метки (например, `67`).

### Как изменить тип словаря в коде/запуске?
Вы можете передать тип словаря при запуске через аргумент `aruco_dictionary`. Поддерживаются стандартные типы OpenCV (например, `DICT_4X4_100`, `DICT_5X5_250`, `DICT_6X6_250` и т.д.):
```bash
ros2 launch fake_tag_publisher run_localization_video.launch.py aruco_dictionary:=DICT_6X6_250
```

### Как добавить или удалить метку?
Откройте файл [tags_config.yaml](file:///home/panik_bel/ros2_ws/src/fake_tag_publisher/config/tags_config.yaml):
* **Чтобы добавить:** Вставьте новую секцию под `tags:`, указав её ID и точные координаты на карте (положение на потолке):
  ```yaml
    tag_67:
      x: 0.0          # Координата X на карте (в метрах)
      y: 0.0          # Координата Y на карте (в метрах)
      z: 2.5          # Высота потолка (в метрах)
      roll: 3.1415926 # Разворот вниз лицом (180 градусов в радианах)
      pitch: 0.0
      yaw: 0.0        # Угол рыскания (ориентация метки относительно оси X карты)
  ```
* **Чтобы удалить:** Просто сотрите или закомментируйте (символом `#`) соответствующий блок `tag_ID:`.

## 3. Запуск локализации (Видео и Живая камера)

Благодаря гибкой системе параметров, ноду локализации можно запускать как на предзаписанных видеороликах, так и в реальном времени с физической камеры.

### 3.1. Запуск по предзаписанному видеофайлу
Это удобно для тестирования алгоритмов фильтрации на одном и том же наборе данных.

1. Положите новое видео в папку `src/fake_tag_publisher/config/` (например, `new_drive.mp4`).
2. Запустите лонч-файл с указанием пути к видео:
   ```bash
   ros2 launch fake_tag_publisher run_localization_video.launch.py \
     video_path:=src/fake_tag_publisher/config/new_drive.mp4 \
     loop_video:=False \
     filter_alpha:=0.15
   ```
   * `loop_video:=False` — видео проиграется один раз, после чего нода сохранит статистику, построит график и завершит работу.
   * `filter_alpha:=0.15` — коэффициент сглаживания (рекомендуемый диапазон: `0.1` - `0.3`).

### 3.2. Запуск в реальном времени с живой камеры
Для работы с физической CSI-камерой на Raspberry Pi 5 необходимо использовать специальную утилиту совместимости `libcamerify`.

Выполните команду на Raspberry Pi:
```bash
libcamerify ros2 launch fake_tag_publisher run_localization_video.launch.py \
  video_path:=0 \
  loop_video:=False \
  filter_alpha:=0.15
```

**Особенности работы с живой камерой:**
* `video_path:=0` — индекс камеры (благодаря встроенному автоматическому приведению типов, вы можете передавать как число `0`, так и путь к устройству `/dev/video0` без риска получить ошибку типов `InvalidParameterTypeException`).
* `libcamerify` — обязательный префикс перед `ros2 launch`, который перехватывает вызовы V4L2 и транслирует форматы официального драйвера PiSP Raspberry Pi в стандартный поток, понятный OpenCV.
* **Сохранение траектории по `Ctrl+C`**: при работе с живой камерой процесс не завершится сам. Когда вы закончите движение робота, просто нажмите `Ctrl+C` в терминале малины — нода перехватит сигнал, рассчитает пройденное расстояние и автоматически сохранит график вашей поездки в файл `trajectory_plot.png`.

## 4. Анализ графиков траектории

Когда вы запускаете видео с параметром `loop_video:=False`, в конце воспроизведения нода локализации автоматически производит математические расчеты пути:
1. Вычисляет общую длину пути по сырым (зашумленным) координатам.
2. Вычисляет общую длину пути после фильтрации низких частот (EMA + Slerp), убирая sub-centimeter "дребезг" маркеров.
3. Строит сравнительный график траекторий.

### Где посмотреть график?
График сохраняется автоматически в двух местах:
1. В папке исходного кода: [trajectory_plot.png](file:///home/panik_bel/ros2_ws/src/fake_tag_publisher/config/trajectory_plot.png)
2. В папке сборки (share): `install/fake_tag_publisher/share/fake_tag_publisher/config/trajectory_plot.png`

Вы можете открыть его прямо из файлового менеджера или в VS Code для визуальной оценки сглаживания траектории движения вашего робота.

## 5. Real-Time Web UI (Мониторинг траектории в браузере)

В ноду локализации встроен легковесный веб-сервер для визуализации движения робота в реальном времени. Это позволяет наблюдать за траекторией с любого устройства в локальной сети, обходя любые проблемы с обнаружением топиков через ROS 2 DDS/мультикаст.

### Как пользоваться:
1. Запустите ноду локализации на Raspberry Pi:
   ```bash
   libcamerify ros2 launch fake_tag_publisher run_localization_video.launch.py video_path:=0 loop_video:=False filter_alpha:=0.15
   ```
2. Откройте веб-браузер на вашем ПК и перейдите по адресу:
   ```text
   http://192.168.31.215:8080/
   ```
   *(Или `http://raspberry.local:8080/`)*

### Основные возможности интерфейса:
* 🌐 **Интерактивная 2D-карта**: поддерживает перетаскивание (левая кнопка мыши) и масштабирование (колесико мыши).
* 🎯 **Слежение за роботом**: режим "Автоцентрирование" удерживает робота в центре экрана при движении.
* 🏷️ **Потолочные метки**: отображаются в виде оранжевых квадратов; при попадании в кадр камеры они подсвечиваются зеленым цветом.
* 📈 **Траектория движения**: прокладывается сглаженная неоново-голубая траектория и сырой пунктирный путь (можно скрыть/показать кнопкой).
* 📊 **Панель телеметрии**: выводит точные координаты $X, Y, Z$, угол $Yaw$, длину пути (сырого и сглаженного) и текущие обнаруженные маркеры.

## 6. Утилиты записи и стриминга на Raspberry Pi

В файл автозапуска `~/.bashrc` на Raspberry Pi добавлены специальные утилиты-сокращения для быстрой работы с камерой по SSH.

### 🎥 Стриминг живой камеры в браузер (`stream`)
Запуск живого видеопотока с камеры для настройки фокуса на объективе:
```bash
stream
```
*   **Как открыть на ПК:** В браузере перейдите по адресу `http://{IP_АДРЕС_RPi}:5000`.
*   **Остановка:** Нажмите `Ctrl+C` в терминале.

### ⏺️ Запись видео с камеры (`video_record`)
Универсальная команда записи видеопотока с камеры с возможностью одновременного вывода трансляции в браузер на ПК (для точного прицеливания).
Поддерживает **умный разбор аргументов**: вы можете указывать параметры в любом порядке без лишних кавычек!
```bash
# Использование: video_record [время] [разрешение] [FPS] [путь] [stream]
# (Параметры можно опускать или писать в любом порядке)
```
*   **Запись по умолчанию** (30 секунд, 640x480, 30 FPS, сохранение в файл калибровки, без трансляции):
    ```bash
    video_record
    ```
*   **Запись по умолчанию С ТРАНСЛЯЦИЕЙ в браузер** (без кавычек!):
    ```bash
    video_record stream
    ```
    *(Камера запустит трансляцию на `http://{IP_RPi}:5000` и даст вам 5 секунд на то, чтобы навести камеру на доску, после чего запишет 30-секундный файл).*
*   **Запись на 10 секунд с трансляцией:**
    ```bash
    video_record 10 stream
    ```
*   **Запись с произвольным разрешением, временем и путем:**
    ```bash
    video_record 1280x720 10 ~/my_test_drive.mp4 stream
    ```

### 🎬 Просмотр записанного видео (`video_stream`)
Запуск циклического воспроизведения любого `.mp4` видеофайла с Raspberry Pi в браузере на ПК:
```bash
video_stream {путь_к_файлу_mp4}
```
*   **Пример просмотра калибровки:**
    ```bash
    video_stream ~/ros2_ws/src/fake_tag_publisher/config/calibration.mp4
    ```
*   **Как открыть на ПК:** В браузере перейдите по адресу `http://{IP_АДРЕС_RPi}:5000`.
*   **Остановка:** Нажмите `Ctrl+C` в терминале.

### 🔋 Мониторинг заряда батареи (`bat`)
Запуск мониторинга состояния аккумулятора платы питания (UPS HAT) робота:
```bash
bat
```
*   **Что делает:** Запускает скрипт `bat.py` и регулярно выводит в консоль текущие параметры питания (процент заряда, напряжение и ток).

## 7. Безопасная синхронизация файлов (Перенос кода с ПК на RPi)

При переносе кода с вашего ПК на Raspberry Pi очень важно **не перезаписать** видеоролики и файлы калибровки, которые были записаны или сгенерированы непосредственно на роботе.

Для этого используйте безопасную команду `rsync` с исключениями (`--exclude`). Запускайте её **на вашем ПК**:

```bash
rsync -avz \
  --exclude build \
  --exclude install \
  --exclude log \
  --exclude "*.mp4" \
  --exclude "*.h264" \
  --exclude "camera_info.yaml" \
  --exclude "trajectory_plot.png" \
  /home/panik_bel/ros2_ws/ raspberry@192.168.31.215:~/ros2_ws/
```

### Что исключает эта команда:
*   `build`, `install`, `log` — папки сборки (они должны компилироваться на процессоре RPi).
*   `*.mp4`, `*.h264` — ваши записанные тестовые и калибровочные видеофайлы на Raspberry Pi не будут затерты пустыми файлами с ПК.
*   `camera_info.yaml` — ваши точные результаты калибровки камеры на роботе будут в безопасности.
*   `trajectory_plot.png` — сгенерированные графики поездок на роботе не будут перезаписаны.

### 🔄 Обратная синхронизация (Копирование калибровки с RPi на ПК)
Если вы хотите скопировать файл калибровки или график поездки с робота обратно на ваш ПК для анализа или бэкапа, выполните **на вашем ПК**:
```bash
# Скопировать файл калибровки
scp raspberry@192.168.31.215:~/ros2_ws/src/fake_tag_publisher/config/camera_info.yaml /home/panik_bel/ros2_ws/src/fake_tag_publisher/config/

# Скопировать график траектории
scp raspberry@192.168.31.215:~/ros2_ws/src/fake_tag_publisher/config/trajectory_plot.png /home/panik_bel/ros2_ws/src/fake_tag_publisher/config/
```
